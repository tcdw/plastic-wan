4. **Admin 后端**：`src/ingress/admin/providers-admin.ts` + `server.ts` 路由；`SecretStore` 注入与明文凭据注册；在用预检；`POST /restart` 与退出码 75；`test/admin-providers.test.ts`（12 个用例）。
5. **Admin 前端**：`apps/admin-next` 的 Models 页（`pages/models.tsx` + `components/models/**`）、新建 Provider 向导、待重启横幅与「立即重启」、`lib/model-manager.ts` 纯逻辑与单测、`e2e/08-models.e2e.ts`；旧的 `pages/model.tsx` 与 `GET /model` 删除（`PUT /model` 保留，供模型行调用）。

## 前端交付细节

- 页面：左栏 Provider 列表（搜索、Agent/Vision 在用徽章、待重启徽章），右栏连接卡片 + 模型表格（👁/💡、context、max output、在用徽章、四个行内操作）；移动端先列表后详情。
- 凭据：API Key 与 header 值都是 `type="password"`、`autocomplete="new-password"`、无查看按钮，提示「已设置，留空以保持当前设置」；请求完成后立即从 React state 与 mutation cache 里清掉明文；改 `base_url` 时前端与服务端**都**强制重填 key 与全部已有 header 值。
- 获取模型列表：已保存模式与临时模式可切换（待重启时默认临时模式并解释原因）；草稿带来源标签与「需确认」拦截，未确认的字段不能提交，必须先过编辑弹窗。
- 编辑弹窗：元数据字段带来源标签；「高级设置」按模型 API 只显示适用字段，三态（自动 / 开 / 关，枚举为 自动 / 具体值），「自动」等于不写该字段。
- 保存反馈：有待重启字段时一律显示「已保存，待重启」并列出路径，绝不说成已生效；`409 config_conflict` 显示「配置文件已被修改」并重新拉取。
- 重启横幅：`supervised` 为 true 时才显示「立即重启」；点击后轮询等待服务恢复。

前端未覆盖的三处（计划未强制，记录在此）：

- 「填写 API Key 后获取模型列表」空态在正常配置下不可达（两种 kind 的 `models` 都是 `minItems: 1`），因此没有 e2e。
- 「设为 Vision 模型」按钮只判断 image 能力；`GET /providers` 不返回 `vision.max_output_tokens`，超出上限由服务端 400 `max_output_tokens_exceeded` 说明。
- 「立即重启」的轮询路径没有 e2e：夹具的 `requestRestart` 只记录调用而不退出进程，e2e 只断言按钮与横幅可见。

## 实施时核实的外部字段（计划「需核实的外部字段」）

| 项 | 结论 |
| --- | --- |
| Anthropic `GET ${base}/v1/models` | **未用真实凭据验证**（本机没有 Anthropic key）。实现按计划表：`x-api-key` + `anthropic-version`，响应 `{ data, has_more, last_id }`，用 `limit` / `after_id` 翻页，最多 20 页、2000 个模型。需要在真实环境里跑一次 `POST /api/providers/discover` 复核。 |
| Gemini `GET ${base}/models` | **已用真实 key 验证**：`{ models: [...], nextPageToken }`，`pageSize`/`pageToken` 翻页，`name` 形如 `models/gemini-3.7-flash`，`inputTokenLimit`/`outputTokenLimit`/`supportedGenerationMethods` 都在，并且**存在表示思考能力的 `thinking: true` 字段**——所以 Gemini 的 `reasoning` 由列表直接给出，不必查 models.dev。只保留 `supportedGenerationMethods` 含 `generateContent` 的模型（41 个里有 13 个在 models.dev 里查不到元数据，会标「需确认」）。 |
| Vercel AI Gateway 的缓存价格 | **有**：`pricing.input_cache_read` 与 `pricing.input_cache_write`（253 个 language 模型里 189 个带缓存价格）。`type` 字段需要过滤（376 个模型里 253 个是 `language`）。 |
| OpenRouter 顶层 `reasoning` | 446 个模型里 314 个带该对象（`mandatory`、`supported_efforts`、`default_effort`）。其中 3 个（`rekaai/reka-edge`、`qwen/qwen3-max`、`qwen/qwen-plus-2025-07-28`）有 `reasoning` 却不在 `supported_parameters` 里。按计划继续用 `supported_parameters` 判定 `reasoning`。 |
| Vercel AI Gateway 列表端点是否需要凭据 | 计划写「无凭据也返回 200」，**现在已不成立**：不带 `Authorization` 仍是 200，但带一个无效的 `Authorization: Bearer …` 会 401。实现总是发送配置里的 key，所以无效 key 会以 401 失败（错误经脱敏后返回），这是预期行为。 |

## 与计划的偏差与实现选择

计划允许在「更小、更一致」时调整实现选择，逐条记录如下。

1. **`needs_confirmation` 不含 `name`**：显示名是装饰性字段，模糊匹配出来的名字不强制管理员重打；`reasoning`/`input`/`context_window`/`max_tokens`/`cost` 仍然一律标记。
2. **`thinking_format` 只开放计划列出的 7 个值**：Pi 0.84.2 的联合类型还多一个 `ant-ling`，计划未列出，因此不开放。
3. **删除最后一个 header 时同时删除 `headers` 键**：否则文件里会留下 `"headers": {}`。
4. **`GET /providers` 多返回一个 `supervised` 布尔**：界面据此隐藏「立即重启」按钮（计划要求「部署方未声明监督时隐藏」，但没规定由哪个字段承载）。
5. **`POST /providers/discover` 与 `POST /providers/lookup-metadata` 不需要 `If-Match`**：它们是读形态的 POST，不写文件，也没有可竞争的 revision。
6. **写端点响应 = `GET /providers` 视图 + `apply` 摘要**：计划要求「响应带上 apply 摘要和新的 revision」，一次往返同时刷新页面更省事，也避免前端拿到旧 revision。
7. **待重启路径的粒度取决于进程历史**：新建/删除 Provider 或改连接字段后，`restart_required` 在**同一进程**里报 `providers.<alias>`（restart 字段不进入 candidate，`activeFile` 学不到它），重启之后才细化成 `providers.<alias>.base_url` 这种叶子路径。计划里的示例属于后者。
8. **builtin 引用未注册的模型现在是文件级错误**：`validateModelReference` 不再对 builtin 提前返回，所以 `agent.model` 指向 builtin 没列出的模型会在 `loadConfig` 阶段失败（`config_invalid`），而不是等到 reload 的 `model_unusable`。测试 `config-reload.test.ts` 的对应用例已按新语义改写。
9. **写端点请求体上限 512 KiB**：审计端点的 8 KiB 装不下模型列表，`readJsonObject` 增加可选上限参数。
10. **`doctor` 探测所有 Provider**：原来只探 custom；现在 builtin 也有配置里的模型列表，因此同样探测。没有任何 text 能力模型的 Provider 跳过（只做 vision 用）。
11. **`GET /model` 删除后 `PUT /model` 保留**：`PUT /model` 仍返回当前模型与可切换列表（`current` + `options`），前端在模型行上调用。
12. **models.dev 不可用时降级而不是报错**：目录只是元数据来源之一，拉取失败时 `discover` / `lookup-metadata` 仍返回列表，把只有该目录能填的字段标成「缺失」并要求确认，同时在响应里给出 `metadata_source_error`（经脱敏），前端在弹窗里显示一行提示。否则离线环境下面板无法添加任何模型——「获取模型列表」与「手动添加」都会失败。
13. **builtin 与 custom 的模型列表结构校验共用 `assertModelConfig`**（config.ts 导出），Admin 写端点在写文件之前就能返回 400 `invalid_model`，而不是等到临时文件校验失败。

## 待决问题的结论

1. **Pi 与 models.dev 的 provider id 映射表**放在 `src/platform/model-metadata.ts`，只收录能进入预设列表的差异项，共 7 条：`vercel-ai-gateway→vercel`、`together→togetherai`、`kimi-coding→kimi-code-plan-global`、`zai-coding-cn→zai-coding-plan`、`qwen-token-plan→alibaba-token-plan`、`qwen-token-plan-cn→alibaba-token-plan-cn`、`qwen-token-plan-individual→alibaba-token-plan`。映射用 Pi 目录与 models.dev 的模型 id 重合度验证过（例如 `qwen-token-plan` 与 `alibaba-token-plan` 是 16/16 重合）。另有 10 条 host → models.dev provider 的映射，供 custom 中转站使用（`openrouter.ai`、`ai-gateway.vercel.sh`、`api.anthropic.com`、`api.deepseek.com`、`api.moonshot.ai`、`api.moonshot.cn`、`api.openai.com`、`api.together.ai`、`api.z.ai`、`generativelanguage.googleapis.com`）；`ant-ling` 在 models.dev 里没有对应 provider，按「中转站」处理。
2. **模型排序**：按配置顺序展示（`GET /providers` 直接给出文件里的顺序），发现弹窗与元数据列表按模型 id 排序。没有做系列分组。

## 关于 `requires_reasoning_content` 预填的已知缺口

计划把 models.dev 的 `interleaved` 当作 reasoning content 回放的唯一预填来源。核实后有三点需要记录：

- `interleaved` 有三种形态：`{ field: "reasoning_content" }`（1003 个）、`{ field: "reasoning_details" }`（15 个）、以及裸 `true`（87 个，Vercel 与部分中转站）。实现只把第一种映射成 `requires_reasoning_content: true`；后两种无法得知字段名，留在「自动」（符合计划的取舍）。
- **models.dev 会漏掉 Pi 目录里明确需要回放的模型**：`openrouter` 下的 `deepseek/deepseek-v4-flash-0731`（dev 配置正在用的 agent 模型）在 models.dev 里没有 `interleaved`，而 Pi 的目录给它标了 `requiresReasoningContentOnAssistantMessages`。屏蔽 Pi 目录后，这个覆盖只能由管理员手工写进配置——`dev-data/config.jsonc` 已经补上。
- 反向不一致也存在：Pi 认为 `moonshotai/kimi-k2.6` 需要 `reasoning_content`，models.dev 写的是 `reasoning_details`，因此面板预填为「自动」。

## 已接受的代价与风险

- **面板写入明文会覆盖 env / command 引用**，且页面上看不出环境变量不再生效；改 `base_url` 会强制重填凭据，从而把 `env` / `command` 降级成明文。已在 [admin-panel.md](../admin-panel.md) 写明。
- **没有「上次可用配置」回退**：`POST /restart` 只保证「磁盘上的配置能通过启动流程的校验」，拦不住启动期才失败的情况（SecretRef 解析失败、Pi 升级导致 builtin 预设消失等）。这类失败会让 bot 停住，等待人工修复。计划已确认接受，交付时再次确认。
- **Anthropic 列表端点未用真实凭据验证**（见上表），首次在真实 Anthropic 兼容中转站上使用时需要复核翻页参数。
- Provider 连接字段、Provider 新增/删除仍然是 restart 字段；热更新留到下一阶段（计划「后续阶段」）。
